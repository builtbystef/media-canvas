# Architecture

The modules of this system, and the seams between them. Update this file when the shape changes. Audits compare it with reality.

## Modules

A pnpm + uv monorepo. TS projects live under `apps/*` and `packages/*` (pnpm workspace); Python projects register in the root `pyproject.toml` (uv workspace). Shared TypeScript compiler presets live in `tsconfig/`.

- **`apps/web`** — the Next.js editor. Renders the compiled document in the browser; talks to the backend only through `@media-canvas/api-client`. Styled with Tailwind v4 and shadcn/ui's Base UI variant: the theme is stock shadcn tokens in `app/globals.css`, declared under `prefers-color-scheme` because there is no toggle, and the registry's components are owned source under `components/ui`. `app/shadcn.css` is the one vendored file — its header says why.
- **`apps/api`** — FastAPI. Owns the Postgres schema and its Alembic migrations, and is the only Postgres writer (ADR-0005). Produces BullMQ tasks (ADR-0004). Never interprets document internals (ADR-0003). Also owns the whole access layer — OTP sessions, Workspaces, Memberships and Roles, invites, and API keys (ADR-0009) — and is the only service that reads asset rows or knows object-storage keys: every asset and output byte a client receives is proxied through it, never presigned.
- **`apps/worker`** — the render worker: Node + Playwright driving pinned headless Chromium (ADR-0002). Consumes per-Row BullMQ tasks and reports results through an internal api endpoint; holds no database client. Uploads render outputs to object storage directly, and exposes a small internal HTTP service (row validation, synchronous render, font inspection) the api calls. Synchronous render and the queue consumer share one pool of eight pages. `render(svg, options)` is the last pipeline step: compiled markup in, one PNG, JPEG, or PDF out. It ships as one pinned image (`Dockerfile`): a base image pinned by digest, the Playwright package with the browser builds paired to it, fontconfig pointed at the bundled set and nothing else, and a fixed viewport, device scale factor, locale, timezone and color scheme. `environment.json` records that environment tuple, and the checks in `src/checks` — run inside the image — hold the image to it, including the render seam and the golden-image suite. Baselines live in `goldens/baselines` as lossless PNGs; they are baked by a separate command that refuses to run outside the image, and the re-bake policy is in `goldens/README.md`.
- **`packages/core`** (`@media-canvas/core`) — the shared TypeScript core (ADR-0003): Design Document schema types, validation, forward-only schema migrations at load, value substitution, and the JSON→SVG compiler. Imported by `apps/web` and `apps/worker`; the single place render fidelity is defined.
- **`packages/fonts`** (`@media-canvas/fonts`) — the bundled font set: the nine SIL OFL families vendored as static TTFs, and the manifest naming each file's Font Asset id (the SHA-256 of its bytes), family, weight, and style. The compiler's metrics, the worker's font configuration, the golden fixtures, and Workspace seeding all read that manifest instead of file names.
- **`packages/api-client`** (`@media-canvas/api-client`) — TypeScript client generated (`@hey-api/openapi-ts`) from the committed `apps/api/openapi.json`.
- **Root Compose stack** — the default services are development infrastructure (Postgres, Redis, and Garage). The `app` profile adds repository-built api, web, and pinned worker images plus Caddy, the only public application origin. Caddy sends `/api` and `/assets` paths to the api and all other paths to the web app; a configured `DOMAIN` activates its automatic HTTPS.

## Seams

- **web ↔ api**: the OpenAPI contract. `apps/api`'s build dumps `openapi.json`; `packages/api-client`'s build regenerates the typed client; both are committed, and CI's contract job fails on drift.
- **api ↔ worker**: Redis/BullMQ carries the work signal only; Postgres holds the state (ADR-0004). Results flow back over the internal api endpoint (ADR-0005).
- **web & worker ↔ core**: both sides render exclusively through `@media-canvas/core`, so editor preview and worker output cannot drift (ADR-0002/0003).
- **api & worker ↔ object storage**: an S3-compatible store (Garage in the compose stack) holds asset bytes and render outputs under per-Workspace prefixes. The api creates buckets at startup, writes and serves asset bytes, and deletes by prefix; the worker writes outputs and reads asset bytes only through the api's internal asset route — clients never see a storage URL or credential.
- **api ↔ mail**: the Mailer seam (ADR-0009) — one interface with exactly two messages (OTP code, Workspace Invite) behind a `MAILER` env var choosing the console (default), Resend, or SMTP driver. Tests assert against a recording fake.
- **browser ↔ application origin**: `tools/browser-smoke` drives an independently installed Playwright Chromium against the full Compose stack. This on-demand seam is reserved for cookie, whole-document navigation, DOM gesture, and browser-history behavior that the pure web modules cannot observe; it is not part of CI or the render worker's fidelity pin.
