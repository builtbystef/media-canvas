# 0009 — v1 is multi-tenant with OTP-only sign-in, no admin, no billing

**Context.** The roadmap originally kept multi-tenant SaaS features out of the MVP: a single-user, self-hosted app whose design merely must not block productizing. When auth was pulled into v1 (roadmap node ejy8hn), the user redirected the goal: be "most of the way to a hosted SaaS" from the first version, so productizing later adds a payment wall rather than architecture. Tenancy is the kind of decision that ripples through every table, storage key, and route — retrofitting it later is the expensive path.

**Decision.** v1 ships full multi-tenancy and RBAC: Workspaces are the tenants that own all content, Users hold per-Workspace Memberships with a Role (Owner / Editor / Viewer), and everything is self-serve — open signup, any User creates Workspaces, Owners invite by email; there is no instance admin, no seed step, and no billing, plans, quotas, or metering. Sign-in is email OTP only, with no passwords; codes and invites are sent through a Mailer seam in the api with three drivers selected by a `MAILER` env var — `console` (default, prints to the api log), `resend` (`RESEND_API_KEY`), and `smtp` — so a self-hosted stack never requires an external SaaS to sign in. API keys are Workspace-owned and cover only the generation surface. Restricting access to a self-hosted instance is the deployer's job at the network layer, outside the app.

**Reason.** Tenant columns, per-workspace asset identity, and route scoping are near-free to build now and prohibitive to retrofit, while billing bolts on cleanly later — so the line is drawn at money, not at tenancy. OTP deletes password hashing, reset flows, and out-of-band invite links; the Mailer seam keeps that from binding sign-in to one vendor, and it stays cheap because the app sends exactly two message kinds (OTP code, Workspace Invite). Rejected alternatives: single-user auth from `.env` (contradicts the SaaS goal), an instance-admin/invite-only gate (adds a concept productizing would delete), and an in-app signup allowlist (network-layer concern smuggled into the app).
