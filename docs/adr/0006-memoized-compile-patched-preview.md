# 0006 — The editor previews by memoized compile and a patched DOM node

**Context.** The core spec (ADR-0002, issue `1qoccb`) commits the editor to rendering the shared compiler's SVG inline, so that nothing the editor shows can differ from what the worker renders. That compiler does its own text layout with opentype.js — cheap for a batch renderer at one compile per asset, unproven for an editor at one compile per gesture frame. The prototype on branch `prototype/editor-preview` (node `vnmueh`) measured five preview strategies across documents from 26 to 236 elements.

**Decision.** Editor document state is immutable per element: an edit replaces the changed element and its ancestor groups, and nothing else. Compilation memoizes on element object identity, in two caches — text line breaking and emitted markup. A gesture frame recompiles only the dirty element and replaces only that element's DOM node; a change that dirties the whole document (load, font change, canvas resize) does a full compile. Selection handles, guides, and marquee live in an HTML overlay above the inline `<svg>`, never inside it; hit-testing runs `elementFromPoint` against the SVG.

**Reason.** Text layout is the entire cost — 6.4 ms of a 9.3 ms full compile at 48 elements, 20.7 of 28.9 at 120 — and it scales with the number of text elements. Memoizing on identity cuts it to 0.3 ms, and patching one DOM node instead of re-parsing the document keeps every gesture under 1 ms at every size measured, so frame cost stops scaling with document size. Full recompile per frame was rejected despite being simpler: it holds 60 fps only to ~60 top-level elements and leaves no headroom for the rest of the frame. A cheap approximate surface during gestures was rejected outright rather than traded against, because it is unnecessary — the patched DOM was verified identical to a from-scratch recompile, worst bounding-box delta 0.0000 px across 236 elements, so the parity guarantee costs nothing. The overlay beats handles inside the SVG on behaviour, not speed (they measured the same): a re-render destroys in-SVG handles mid-gesture along with their pointer capture and focus. The accepted cost is that the editor's state model is not free to mutate elements in place — memoization is load-bearing, not an optimization.
