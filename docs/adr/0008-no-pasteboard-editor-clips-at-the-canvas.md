# 0008 — The editor clips at the canvas edge; there is no pasteboard

**Context.** Every comparable design tool (Figma, Illustrator, Canva) surrounds the artboard with an infinite pasteboard where off-canvas content stays visible as a staging area. This editor renders the shared compiler's SVG inline (ADR-0002, ADR-0006), and that SVG is exactly the markup the worker screenshots — its viewport is the canvas. Showing off-canvas content would mean drawing something outside the render markup, on a surface the worker has no equivalent for.

**Decision.** Elements positioned partly or wholly outside the canvas are clipped in the editor exactly as they are clipped in the exported asset. There is no pasteboard, no dimmed overflow region, and no second drawing surface. Off-canvas elements remain reachable through their row in the layer list and through their selection handles, which live in the HTML overlay above the SVG and are positioned from element bounds regardless of visibility.

**Reason.** A pasteboard is a region whose contents are not in the output, which is the editor-versus-render gap this project spends its entire architecture closing; a designer who stages work there is looking at pixels no render will ever produce. The accepted cost is real — dragging an element off the edge makes it vanish rather than park — and it is paid down by the overlay, which keeps handles and hit targets alive for elements the SVG no longer draws, so nothing becomes unrecoverable. Rejected alternative: rendering overflow at reduced opacity outside the canvas bounds, which requires a second compile target with different clipping and reintroduces exactly the divergence the single-markup rule exists to prevent.
